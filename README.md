# A311Y3 低功耗常开音频感知引擎

在晶晨 **A311Y3**（ADLA3，8 TOPS NPU）上做一套**按功耗预算设计**的常开声学事件感知系统：深睡门控 → 候选生成 → NPU 突发确认 → 按事件代价告警。

主线不是"在板上跑通一个音频分类器"，而是三件事：

1. **前端一致性**：PC 与板端的 Log-Mel 逐元素对齐到 1e-3，掉点归因到具体实现差异，而不是含糊的"量化损失"；
2. **能量而非延迟**：常开系统的成本是占空比和误唤醒次数，不是单窗推理快几毫秒；
3. **模型是自己裁的**：从 CNN14 蒸馏到 0.4 M 参数，宽度按「参数量–精度–延迟」帕累托前沿选，不是从 GitHub 下载。

## 前端一致性实测

`python/mel_parity.py` 用 5 段合成信号（稳态多音 / 扫频 / 脉冲串 / 低 SNR / 静音起音），对比 PC float 参考实现与板端定点模拟实现，逐项量化 9 种常见实现偏差。

单项独立贡献（跨 case 取最坏，特征归一化域）：

| 偏差 | max\|Δ\| | 说明 |
| --- | ---: | --- |
| `top_db_missing` | 1.000 | 不做动态范围截断 |
| `mel_htk_norm` | 0.732 | 用了 HTK 而非 Slaney 面积归一 |
| `log_20` | 0.500 | 20·log10 而非 10·log10 |
| `preemph_skip` | 0.366 | 漏掉预加重 |
| `pad_zero` | 0.264 | 零填充而非 reflect |
| `filterbank_q15` | 0.0156 | 滤波器系数 Q15 量化 |
| `window_symmetric` | 7.9e-3 | 对称窗而非周期窗 |
| `feature_int8` | 3.9e-3 | 特征量化到 int8 |
| `log_lut` | 3.1e-3 | log 用定点查表近似 |

排障路径（从全偏差状态贪心修复）：

```
全错 1.000 ─┬─ 修 top_db_missing ──> 0.818
            ├─ 修 mel_htk_norm   ──> 0.673
            ├─ 修 log_20         ──> 0.363
            ├─ 修 preemph_skip   ──> 0.268
            ├─ 修 pad_zero       ──> 0.0142   ← 已消掉 98.6%
            └─ 其余 4 项         ──> 0.00e+00
```

**结论：消掉 90% 的特征偏差只需修 5 项；全量对齐后残余 0。**

这件事的意义：端侧 INT8 掉点常常被归因成"量化损失"，实际上大半是**两边实现不一致**。把前端对齐之后，量化本身的贡献只剩 3.9e-3 量级——这才是可以拿去谈"量化精度"的基线。

数据见 [`bench/logs/feature_parity.json`](bench/logs/feature_parity.json)，方法论见 [docs/前端一致性.md](docs/前端一致性.md)。

## 分层延迟口径

端到端必须拆成两条曲线，合成一个分位数会互相淹没：

| 曲线 | 含义 | 典型占比 |
| --- | --- | --- |
| `fastpath` | 门控拒绝的窗，只算门控 | 多数 |
| `confirm` | 走完整链路（门控+特征+推理+状态机） | 少数，但决定用户感知 |

在合成集上跑占位模型（**非真实 NPU 数据，仅验证链路**）：

```
glass_break_clean: 78 窗，门控挡掉 45，npu_duty = 42.3%
fastpath  P50 0.004 ms / P99 0.006 ms   (n=45)
confirm   P50 0.094 ms / P99 3.552 ms   (n=33)
```

真实数字要以 `.adla` 上板后的 `bench/logs/e2e_*.json` 为准。

## 功耗口径（务必看完）

开发板是 12V/3A 整板（DDR + PMIC + HDMI + PHY 全在），整板功耗 2–4 W 量级，**不存在 mW 级整机常开**——那是成品板才有的数。

所以本仓库只承认两种口径：

- **A. 活跃占空比**：`cpuidle` 驻留时间 + NPU 调用计数，折算平均功耗（可复现、可进 CI）
- **B. 整板平均功耗**：INA226 串在 12V 输入实测

两者都必须和"NPU 全程常开"的基线对比，否则数字没有意义。详见 [docs/功耗口径.md](docs/功耗口径.md)。

## 版本纪律

```yaml
SoC            : A311Y3
NPU 代际       : ADLA3            # 不是 ADLA2，产物格式不同
target_platform: "007"            # AMLNN 平台表中 A311Y3 的 id
ADLA driver    : >= 2.0.2
NNSDK          : >= 3.0.0
NNSDK2         : >= 1.0.0
模型产物       : .adla
```

`python/convert_adla.py` 会把指纹写进产物的 `*.fingerprint.json`，交付时一并附上。**版本不成对时的典型表现是加载成功但输出全 0 或形状错乱**，不是报错——所以必须留指纹。

## 模型选型为什么是纯 CNN

`python/probe_operators.py` 的算子清单里，高风险项集中在两处：**GRU/LSTM**（ADLA 系对循环结构支持弱，会 fallback 到 CPU，届时"NPU 加速"名存实亡）和**图内前端**（STFT / MelFilterBank，没必要塞进计算图）。

所以模型锁定纯 CNN（BC-ResNet 系），时序信息靠感受野而不是循环结构。这是**部署约束倒推模型结构**，不是精度妥协——这个决策要能讲出来。
