# 实施计划

10 周（2026.10 – 2026.12）。原则：**每周结束时必须有一个能贴进简历的数字，否则说明这周白干。**

| W1 | 算子探测（`--emit-onnx` + `--try-convert`） | 18 项全部有实测结论 | 同上 |
| W1 | ALSA 采集 + `arecord -l` | `cpp/` 能录到 5 s PCM | — |

## 每阶段的验收口径

| 指标 | 口径 | 采集方式 |
| --- | --- | --- |
| 前端一致性 | 特征归一化域 max\|Δ\| < 1e-3 | `mel_parity --c-dump` |
| INT8 掉点 | 同一 eval 集，float vs int8 的 mAP 差 | `eval_events.py` |
| 单窗延迟 | 预热 20 窗后取 P50/P99 | `board_infer.py --json` |
| 端到端 | fastpath 与 confirm 分开报 | 同上 |
| 占空比 | NPU 调用窗 / 总窗 | 同上 |
| 平均功耗 | cpuidle 驻留 或 INA226 | `board_power_budget.py` |
| 误唤醒 | 负类长跑，次/小时 | `eval_events.py --negatives-only` |

## 依赖与阻塞

| 依赖 | 影响 | 拿不到时 |
| --- | --- | --- |
| A311Y3 开发板 | 全部板端数据 | 先在 x86 跑前端与模型，板端后补 |
| AMLNN Toolkit（PC） | `.adla` 产物 | 用 ONNX Runtime 出 CPU 基线，标注口径 |
| NNSDK2（板端） | 真实推理 | C++ 侧用占位 score，只验证调度与打点 |
| HiFi5 可编程 | 域 1 前移 | A55 小核，文档注明 |
| always-on RISC-V | μW 级门控 | A55 深睡，功耗从 μW 提到低 mW，叙事不崩 |

**叙事不押在任何一颗未开放的核上**：域切分是方法论，用哪颗核实现是工程现实。

## 反模式（写在这里防自己）

- 先跑通模型再想前端 → 掉点无法归因
- 用整板功耗宣称 mW 级常开 → 一问就穿
- 把 fastpath 和 confirm 合成一个 P99 → 数字好看但没意义
- 只测正类不测负类 → 上线第一天就被投诉
- 没有 `bench/*.json` 就往简历写数
