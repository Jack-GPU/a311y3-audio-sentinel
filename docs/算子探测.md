# 算子探测：先探再选，别反过来

## 为什么单独做这一步

部署失败最常见的路径不是"模型精度不够"，而是"结构里有个算子落不到 NPU 上，fallback 到 CPU 之后整体比纯 CPU 还慢"。

这类问题在上板之前完全看不出来：ONNX 导出成功、toolkit 转换"成功"、加载也成功，只有跑起来才发现某一层在 CPU 上。

所以顺序必须是：**算子体检 → 定结构 → 训练 → 转换**。

## 怎么用

```bash
# 1) 静态风险清单（随时可跑，不依赖 SDK）
python python/probe_operators.py

# 2) 生成最小探测模型
python python/probe_operators.py --emit-onnx --onnx-dir models/probe_onnx

# 3) 在 toolkit 环境逐个真实转换
python python/probe_operators.py --try-convert --onnx-dir models/probe_onnx \
    --calib data/calib/wav_list.txt
```

第 3 步产出 `bench/logs/operator_probe.json`，里面 `converted: true/false` 才是真值。静态表的 `risk` 只是先验。

## 已知的风险分布

| 类别 | 算子 | 风险 | 处理 |
| --- | --- | --- | --- |
| 卷积主干 | Conv2D / DepthwiseConv2D / BN / ReLU | 低 | 直接用 |
| 池化与分类头 | AvgPool / GlobalAveragePool / Gemm / Softmax | 低–中 | Gemm 可退化为 1×1 Conv；Softmax 可移出模型 |
| 一维卷积 | Conv1D | 中 | 改 Conv2D(kernel=(1,k))，把频率轴当 H |
| 形状操作 | Transpose / Resize / Slice | 中 | 尽量固化进前后处理 |
| **时序建模** | **GRU / LSTM** | **高** | **放弃，改纯 CNN** |
| 图内前端 | STFT / MelFilterBank | 高 | 前端留 CPU/DSP，不进图 |

## 关键决策：为什么是纯 CNN

BC-ResNet 系（depthwise separable 2D conv + 频率下采样）能覆盖音频事件的判别需求，而 CRNN 的循环层在 ADLA 系上大概率落不到 NPU。

这里的取舍要说清楚：

> 不是我不知道 CRNN 时序建模更强，是部署约束不允许。选 BC-ResNet 之后我保留了足够的时间感受野（1 s 窗、6 个 block 的膨胀），用结构换掉了循环。

**"部署约束倒推模型结构"这个决策本身，就是端侧工程师和算法同学的区别。**

## 探测结果怎么进到简历/汇报

不要写"支持 Conv2D 等算子"，要写：

> 对 18 个算子做了转换体检，4 个高风险项集中在 RNN 与图内前端；据此把主干从 CRNN 改为纯 CNN，避免了 2 周返工。

有"因为探测结果所以改了什么"，才叫决策；只列清单那叫背景调查。
